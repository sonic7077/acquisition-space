# 评论、需求库与写手关联使用说明

## 使用顺序

1. 在选题库搜索素材，系统沿用现有流程自动采集评论。
2. 在客户线索按博主→作品→评论查看。内容类型与客户意向独立展示，可分别筛选；旧评论可点击“本地重分析评论”，不会重新请求TikHub。人工修正的标签在重采和重分析时保留。
3. 打开需求库，明确选择目标IP，新增业务主题及关键词，再点击“从评论整理需求”。多主题命中按主题创建顺序取第一个，可通过待归类入口人工指定。
4. 在待归类区选择评论并指定主题；未归属IP评论只有经明确选择后才纳入所选IP，原评论的归属及可见权限保持不变。
5. 编辑需求的对应选题、已有资料名称、产品和备注。需求转选题后，审稿页保留需求ID和证据快照。
6. 在“用写手改编”或“IP与写手→创建内容任务”中选择关联需求。预览会分别包含原作品评论与目标IP需求证据。原创写作可选择原创口播文体；复刻口播仍须提供已核对的逐字稿。

## 判定和统计口径

- 内容类型：追问、反对、共鸣、需求、待核实。
- 客户意向：问价格、问方案、要资料、无关、待核实。旧“有意向”值继续保留，但不会自动认定为具体有效需求。
- 明显质疑/否定、广告先排除；其余结合询问或索取表达打标签。符号/表情不计入需求。规则可能漏判或误判，可人工修正，不能把规则建议当作成交判断。
- 有效需求次数只统计问价格、问方案、要资料。反对和共鸣作为单独研究证据展示。
- 同平台同评论ID去重；不同用户说相同原话仍计次数，代表原话去重展示。评论者人数只统计有平台与用户ID的条目，不以昵称推测人数。
- 优先级 = 问价格×3 + 问方案×3 + 要资料×2，是内容策划排序分，不是购买概率。
- 统计按当前可见的原始评论计算，修改正文、标签或主题规则后读取即可反映已有主题的变化；新主题需点击整理以创建对应需求条目。重复整理不会重复建需求。没有有效证据时显示“证据失效”。
- 需求标签不改变contactable，研究评论不会自动变为可跟进客户。

## 写手与权限

既有12问、版本、启用和规则证据门槛保留。新生成SKILL增加“追问正面回答、反对理解顾虑后回应、共鸣提炼表达、需求转选题”的规则。已有启用版本不会被偷偷改写：需要更新时，请重新生成SKILL并由管理员或团队长确认启用。

原话和需求只作洞察，案例、价格、资质等事实仍需本IP已核验知识。未配置联网工具时不声称已联网核查。新功能的标签、主题和整理使用本地规则，不需新增API Key；AI写作继续使用管理员在系统设置中的现有模型配置。

需求按IP隔离。聚合列表只展示当前用户可见的评论；稿件保留的历史快照若含当前无权查看的来源，会隐藏该快照原话与统计。后台写作在请求前后校验需求证据和权限，失效或变更时停止写入。
