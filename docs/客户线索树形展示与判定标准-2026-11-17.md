# 客户线索树形展示与判定标准

## 展示结构

来源博主 → 来源作品 → 评论/线索，默认展开博主，作品按需展开；支持展开/收起全部。搜索与筛选展开匹配分支，同时匹配博主、作品、原文、来源及负责人。每层展示当前匹配数量，保留意向/研究评论/人工登记筛选、查看编辑及跟进记录。单作品超过50条时逐批展开，避免一次铺满页面。

分组优先使用来源博主ID，缺失时从作品关联补全；同名不同ID、不同平台、不同IP分开。未知博主与手工无来源记录单列；失去关联的作品保留原material_id，不把无关作品静默合并。未归属素材仍按后台提交者权限过滤，前端只使用已授权返回记录。

未归属IP评论可直接编辑，编辑页显示真实归属且不可改IP（旧接口原本也不接受改IP）。本次未增加自动外发、资格核验或客户身份合并。

## 当前系统实际标准

| 项目 | 当前行为 | 含义与限制 |
| --- | --- | --- |
| 自动采集评论 | contactable=false，研究评论 | 保留为研究样本，默认不计入工作台可跟进量 |
| 问价格建议 | 包含多少钱、价格、收费、费用 | 无法识别“太贵了不考虑”等否定，也可能是同行调研 |
| 要资料建议 | 包含资料、领取、求链接 | 可能只为学习，不等于购买意愿 |
| 问方案建议 | 包含怎么做、方案、怎么办 | 可能有需求，但尚未验证业务匹配与联系路径 |
| 多类命中 | 问价格优先，其次要资料、问方案 | 单标签匹配优先级，不是意向强弱评分 |
| 未命中 | 待核实 | 没有匹配关键词不代表没有真实需求 |
| 手工新增/历史记录 | contactable未明确false时默认计入原可跟进口径；编辑页新增意向默认有意向 | 登记不等于已核验，因此页面改称人工登记/已标记，原后台统计保持不变 |
| 数量 | 按评论或登记记录计数 | 相同用户跨作品评论可能多条，不是去重客户人数 |

原平台评论即使改为有意向或填写回复，contactable也不会自动变为true；当前界面没有完成客户资格核验的工作流。关键词、点赞、评论量和跟进阶段都不能单独证明有效客户。

## 推荐的有效线索口径（尚未作为硬门槛实现）

1. 原话或咨询证据显示明确需求，能说明客户想解决的问题。
2. 与团队产品、服务范围及目标人群匹配。
3. 有可实际跟进的路径，如已建立私信/咨询联系，而不是只有评论昵称。
4. 经人工核实，排除广告、机器人、同行调研、否定表达或无关评论。

满足后再根据紧急度、购买意愿、预算与决策条件排优先级。建议区分研究评论、待核实意向、有效线索；“有效线索”仍不是成交客户。避免直接把规则命中的研究评论批量转为有效客户。
