# 博主发现、作品规则与帮助中心交付说明

2026-11-19，按已批准的合并设计实施。未替换用户飞书Base，未新增角色或恢复视频生成。

## 可使用的功能

1. **对标博主**：独立页面；平台账号ID、粉丝与有效样本、中位赞、库内作品数、命中关键词与首次/最近发现时间。人工设置分层、备注、启用和“我的账号”，重新采集保留管理决定。关键词入口复用选题库搜索，不提供未接入的主页批量采集。
2. **关键词方案**：每人最多30个私人方案，可保存、恢复与删除；可不选IP。支持逗号、中文逗号、顿号、换行分词，保留英文短语空格；最多5词。每词每平台最多20条，同时受每平台总量20条限制。调用上界包含搜索分页、详情、评论和可选抖音作者详情。保存方案不产生外部调用。
3. **作品推荐**：默认全部与点赞排序不变；新增推荐、起量、低粉高赞和时间待核实筛选，以及样本倍数/综合参考分排序。每条显示公式分母、有效样本、指标、命中理由、排除理由和规则版本。未知/零基线、未知粉丝、未来时间、单轮快照不会伪造对应结论。原始快照保留最近30次，涨赞显示观察间隔。
4. **管理员阈值设置**：系统设置→作品推荐规则。默认倍数3、分母下限100、有效评论20、评赞比高5%/中2%、起量48小时/涨赞300/点赞1000/倍数3、保鲜180天。实际设置同时在素材和帮助解释；配置变更递增版本、不再次调用平台。
5. **评论管理**：保留博主→作品→评论树；新增按点赞/采集时间排序、类型与意向分布、有效需求筛选。显示评论ID、用户ID、发布时间、一级评论范围，以及接口真实返回的父评论ID/回复数。没有新增回复正文采集；研究评论不因筛选而成为客户。人工覆盖依然保留。
6. **飞书字段映射**：支持独立映射评论类型、判定依据、版本、人工覆盖、负责人、采集时间、评论用户ID、范围、父评论与回复数；日期列支持ISO采集时间转换。准备字段操作依然仅由管理员显式触发，默认只补现有三列文本字段，不自动创建上述业务列。
7. **使用说明**：侧栏新增普通成员可见帮助页，按采集、生产、运营组织，包含配置/权限、真实能力边界、指标、评论需求、末级目录、默认8写手与自建写手、审稿版本、单向飞书、发布状态、复盘和已有命令行备份。

## 规则与边界

样本基线仅使用可见且同作者、同平台、同IP范围的作品；未归属资料还按所有者隔离。至少3条有效点赞且中位数大于0才算倍数。推荐不等于爆款认定，评赞比不等于引流或成交，综合分缺失项不贡献分数。本人、停用、已排除/不可用、超过保鲜期或发布时间待核实的作品不进入推荐，仍可在全部研究。

关键词搜索仍可命中本人或停用博主，已经产生的调用不会免除费用。不同平台和账号条件的能力以TikHub实际返回为准。

评论管理推荐获客空间与用户已有飞书三表配合：本系统维护采集、权限、标签和需求证据，飞书用于分组查看和协作。当前本地→飞书单向同步；飞书编辑不会回流，修改同步字段可能触发冲突。双向字段归属和销售CRM需要独立设计。

现有 manage.py 提供一致性数据库、密钥和资产备份，本轮补充说明；未新增每日自动备份、页面恢复、知识引用次数提醒、排期冲突提醒或真实RPA发布。实际发布仍按现有人工凭证流程处理。
