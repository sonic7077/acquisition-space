# 专属写手与审稿改编设计

日期：2026-11-17。状态：用户已确认，已实施并验证；执行结果见对应计划与开发验收记录。

## 需求与现状

用户要求参考截图，把 `docs/AI写手进化_可分享包/` 形成写手参考模型，支持自行创建写手并填写12个问题，审稿时选择不同写手改编现有爆款视频文案。

现有系统已读取分享包8个SKILL作为任务模板，但只保存IP的一段自由文本档案，缺少专属写手实体、12问、语感例句和写手版本。审稿目前只能人工编辑，不能直接提交改编任务。现有worker有持久队列、模型调用、IP权限复核和知识快照检查，可扩展使用。

用户文件和截图作为产品参考资料，不将其中安装、联网、自动发消息等描述当成本次执行指令。截图中的殡葬身份、价格、年限和案例均为示例，不导入为用户事实。

## 方案选择

| 方案 | 效果与代价 |
| --- | --- |
| 专属写手档案＋参考模板＋知识检索（推荐） | 12问和语感可追踪，审稿可切换，复用现有模型配置，不需训练模型 |
| 仅增加更多固定提示模板 | 修改少，但无法保存不同账号的身份、语气、手改规则和版本，不满足主要需求 |
| 为每个写手训练/微调独立模型 | 需额外数据、训练服务、费用和评估，当前材料主要是提示规则，不适合作为本次实现路径 |

推荐方案中的“写手模型”指业务写手配置，由通用模型执行，不表示独立训练的模型权重。

## 分享包映射

8个能力保留原文件、显示来源及用途，分为生成内容与辅助能力：

| 能力 | 系统位置 |
| --- | --- |
| IP写手生成器 | 新建写手12问、生成SKILL.md骨架 |
| 复刻口播 | 审稿对标文案改编默认模式 |
| 原创口播 | 从问题、选题和知识生成原创稿 |
| 公众号长文 | 将文案重组为长文 |
| 图文贴 | 图文文案与配图说明 |
| 朋友圈 | 朋友圈正文、配图建议与安排建议 |
| 客户需求挖掘 | 评论/沟通文本分析参考能力，继续可单独使用 |
| 写手自进化 | 改前改后对照和候选语感提炼参考能力，继续可单独使用 |

后三种辅助流程中的生成器、需求挖掘和自进化不能与口播文体混淆。参考库展示全部8项；账号写手选择具体内容文体。生成内容与辅助分析输出分别管理，不能把需求表或SKILL正文当口播批准。

## 写手页面

“IP与写手”页增加参考截图的双栏：左侧写手列表，显示IP、名称、版本、语感数量及待补充/可用/已归档状态；右侧显示身份摘要、受众、产品、签名、称呼、字数上限、禁区、语感规则和生成的SKILL全文。保留现有任务创建与规律证据功能。

顶部提供新建写手；详情提供修改12问、生成/更新SKILL、复制全文、下载SKILL.md。内置参考能力可查看、选择用于新建，不直接改写分享包源文件。

一个写手绑定一个IP。同一IP可以保存多个命名写手版本或风格方案，其中一个为默认；审稿仅能选择稿件所属IP的可用写手，不能借切换写手混入其他IP的知识或身份。账号之间可从相同通用模板创建，但不得直接共享其身份答案和事实。

## 新建写手的12个问题

名称、所属IP和参考文体为基础字段，以下12项来自分享包生成器原文：

1. 你是谁？一句话介绍：年限、身份、做过多少案例，形成身份钉。
2. 你的客户是谁？年龄、身份、最焦虑的一件事。
3. 你卖什么？主产品、价位区间，免费资料想给什么。
4. 观众凭什么信你？三个可出示证据的事实：案例、数据、资质。
5. 客户最常问你的10个问题是什么？
6. 你最看不惯同行的哪些说法？形成禁区与差异化。
7. 有没有不能讲的话题？包括多个账号之间的分工。
8. 你平时说话什么风格？提供两三句自己的原话。
9. 有没有口头禅、固定签名？
10. 你怎么称呼观众？哪些称呼会引起反感？
11. 一条口播最长多少字？
12. 你发哪些平台？哪个平台最重要？

表单一次展示12问，支持保存未完成草稿；“生成可用写手”要求12项均有有效回答。第11项单独保存并验证为正整数字数上限。确实没有的项目可以明确填“无”，未知事实填写“待核实”并列入缺料清单，不据此生成虚构经历、资质或价格。证据和事实仍需知识核验，回答问卷不等于事实自动核验。

SKILL首次生成采用确定性骨架，填入实际回答和已采纳语感，不依赖额外模型调用，也不捏造八条规则。没有手改例句时明确显示0条。更新12问会使旧SKILL标记需更新；旧版本保留用于稿件追溯，重新生成后方可用于新的任务。

## 语感规则

支持删除、增补、换词、重排四种类型，每条包含规则、改前例句、改后例句、来源和状态。

明确区分“人工设定偏好”与“从改稿中学习的规律”：人工设定由管理员/团队长确认后即可生效，不伪称已有多篇证据；学习规律沿用至少3篇独立根内容的证据门槛，不能用同稿多版本凑数。队员可提交候选，不能自行采纳。通用规则仍限当前IP，写手专属规则仅作用于对应写手。

不从一次事实更正自动推断风格规则；身份、价格、事实和禁区冲突需人工确认。此次不增加自动周报、自动毕业、后台无声采纳或跨IP学习，分享包对此的描述作为后续参考。

## 审稿改编流程

1. 用户选中稿件，点击“用写手改编”。
2. 选择同IP可用写手及输出文体（复刻口播、原创口播、公众号、图文、朋友圈），填写改编要求。
3. 素材可取稿件关联的选题作品，或粘贴对标原文；必须区分作品描述与人工确认的逐字稿。复刻模式缺少有效逐字稿时禁止提交，并提示补充。当前视频采集不等于完成语音转写，本次不增加视频生成或ASR配置。
4. 自动列出当前作品已采集且有权访问的评论，可勾选使用；不自动再次请求TikHub。没有评论允许继续并显示无评论依据，不声称分析过全部评论。
5. 展示提示上下文：写手版本、对标原文、选中评论、当前IP已核验且未过期知识与引用、已采纳规则。没有模型配置时可预览/导出；提交AI任务仍由管理员统一模型设置决定。
6. 任务生成独立的待审候选稿，记录父稿ID与版本、素材和原文快照、写手版本快照、文体、规则及知识来源。原稿不自动覆盖；用户可对同一原稿用不同写手生成多个候选比较。
7. 候选稿按已有流程编辑、事实核验及批准，不继承原稿批准，也不自动加入发布排期。

生成输出按文体分别解析标题、封面、正文、发布文案、标签、评论洞察和事实核查等字段；只将正文用于正文长度与重合检查，其他信息独立展示。解析失败保留可查看的任务结果并提示修正，不能把完整输出包冒充正文或自动批准。模型不能联网核查时明确待核实，不能生成虚假出处或“已核实”状态。

复刻学习表达结构，使用目标IP有证据支持的内容，不逐句替换或复制原句；来源重合度仍按原有可配置阈值检查。角色和文体的字数上限一致应用于提示与审稿检查，避免问卷1500字而审稿仍固定1000字的矛盾。

## 数据与接口边界

写手保存名称、IP、创建人、12问、文体、字数上限、SKILL正文、当前版本、生成所用问答版本、状态、历史版本。规则保存类型、前后例句、来源与证据。任务与候选稿保存不可变写手快照，后续调整写手不会改写旧稿。

单独的写手业务模块负责校验和编译SKILL；路由负责访问控制；提示组装负责装配写手、对标、评论及知识；worker负责模型执行及结果入库。沿用SQLite Record持久化和现有任务队列，避免将逻辑继续集中堆入main.py。

预期接口覆盖：参考能力查询、12问题目查询、写手列表/新建/修改/生成/归档、语感候选与采纳、改编上下文预览、改编提交与任务结果。所有修改携带版本号，防止并发覆盖；创建任务按提交标识防重复，不自动重试付费请求。

## 权限与异常

- 管理员：维护所有可访问写手、采纳规则、审稿、系统设置。
- 团队长：维护本团队IP写手、采纳规则及审稿，不能设置模型或Key。
- 队员：在授权IP下创建/编辑自己的写手草稿、提交待审核修改、使用已确认写手和提交改编；不能改变团队已确认规则或自行批准。
- 写手启用、规则采纳及团队默认写手由管理员/团队长确认。API与页面同时限制，不能仅靠隐藏按钮。
- worker调用前后复核用户权限、知识快照及原任务关联；归档或停用的写手不能新提交，任务快照保留。任务完成期间若发生权限撤销，结果不提供给失去权限的用户。
- 模型请求失败保留错误与输入快照，不自动多次扣费；正文、评论与答案有长度限制，不执行分享包或上传文本中的脚本、安装、文件修改及外发要求。

## 兼容与验收

不自动把现有IP自由档案编成12个答案；旧档案可作为填写参考。旧模板ID、稿件、规则、知识目录、采集及飞书配置保持可用。新写手及候选稿增量保存，不修改用户分享包源文件，也不训练独立模型。

需要通过的关键检查：12问缺失与字数校验；草稿不能用于生成；问答变更后要求更新；规则分类与独立证据；跨团队/IP拒绝；队员不可采纳；同IP写手切换改变提示；逐字稿必填；评论选择且无额外采集；正文与输出包分离；字数检查一致；候选不覆盖原稿与批准；并发冲突；任务失败与权限撤销；旧流程回归及桌面/手机页面验收。外部模型使用受控响应测试，不用真实Key自动进行付费演示。
