# 写手进化

以人工改稿量能否降低为检验目标。只分析本次可见的稿件对照、已采纳规则、平台数据和业务资料。发布指标请有权限的用户提供，或使用任务明确给出的数据；平台后台与系统复盘数据不会自动读入本次分析。保留原稿、定稿、目标 IP、文体及来源编号。

## 四条反馈回路

| 信号 | 怎么分析 | 建议改哪里 |
| --- | --- | --- |
| ① 人工改稿 | 成对比对最后一版 AI 初稿和人工确认的定稿，归纳有证据的表达偏好。 | 提交对应 IP 或写手的语感候选。 |
| ② 发布表现 | 同平台、同账号、同观察窗口，比较同一指标和类似文体，引用对应稿件原句。记录零改动的定稿作为正向人审信号。 | 一次建议试一处变化。表现只能支持候选假设，列明选题、流量、封面、投放等可能影响；相关不代表因果。 |
| ③ 素材缺口与过期 | 找到重复案例、常用说法、过期政策和待核数据。区分缺失、待核、已过期；证据齐备时可建议补充替代资料。 | 列知识补齐、重新核验或归档建议。 |
| ④ 业务与客户变化 | 识别产品、价格、政策、人群、目标 IP 需求或观点变化。说明哪项证据提示变化以及影响范围。 | 事实更新归共享知识，客户问题归目标 IP 需求，身份、口吻、钩子和产品落点按需进入写手版本审核。 |

同作品评论用来理解当前作品的追问、反对、共鸣；已关联的目标 IP 需求用来判断本业务要回答什么；已核验、未过期且适用的共享知识用来核对事实。涉及事实的更正单列，注明当前稿件受影响位置、知识 ID 或待补来源。引用评论和需求时保留脱敏原话，不将观众反馈当作产品或效果证明。

## 从真实手改提炼候选规则

1. 仅使用真实初稿与人工定稿的对应版本，去掉字数统计、栏目标签、排版符号、图注和平台自动附加文字。零改动稿单独计数，不给某条学习规律凑证据。比较两周改稿量时沿用同一种口径，注明样本数；无法可靠计算时说明缺什么。
2. 逐处标出删除、增补、替换和重排。去掉专有名词和本篇数字，仍可复用的写法才适合进入候选。事实更正走知识；固定换词或禁词按需要单列为人工检查建议。
3. 区分目标 IP 可跨文体的偏好、仅在某平台或某写手内成立的偏好，以及一次性调整。用「位置＋触发条件＋具体动作」写成一句话，附一组脱敏的改前、改后短例及稿件编号。
4. 按独立内容根计数，同一作品的多次修改、候选版本及稿件分支合并计算。相同改法在至少 3 篇不同根内容出现且有真实前后对照时，可建议提交学习规则。一两篇留待积累。平台数据或零改动不能替代这 3 篇手改证据。
5. 将和现有规则冲突、涉及身份、价格、联系方式、数字或平台规则的事项列为人工确认。证据充分也只给候选建议；已有规则建议合并、归档或回退时附理由和证据。

## 发布数据怎么看

用户提供播放、曝光、点击、完读或完播、互动、咨询等指标及对应稿件时，再做对照。点击或打开信号先看标题、封面、首图；完读或完播先看开头和结构；收藏、分享或评论先看观点和表达；咨询先看结尾与服务落点。样本和口径足够时可选效果靠前和靠后的各两条，引用原句并说明其他解释；缺关键分母、观察窗口或对应文稿时列缺口。

## 输出与人工采纳

用 Markdown 输出一份复盘报告，依次列出：

1. **改稿情况**：样本期、独立内容数、零改动数、可比时的改稿量及口径。
2. **候选规则**：优先列最多 3 条，逐条附范围、改前改后、证据编号与独立内容数。发布对照产生的假设单独注明。
3. **知识与业务更新**：待核、过期、缺口、新需求和产品或人群变化，写出对应处理动作及证据。
4. **需要拍板**：最多 3 个关键决策，给出建议和验证方式；每次只试一个变化。

报告可在「IP与写手」中回看。默认写手需在对应 IP 的「规则与知识增强」提交候选，由管理员或团队长采纳，生成新版本；专属写手的「语感规则」经采纳后重新生成 SKILL 并确认启用。知识和需求按系统页面分别更新。只在用户需要时输出周复盘，不自行写文件、更改生效规则、定时或发送报告。
