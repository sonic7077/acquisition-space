# 获客空间

中文本地网页系统，采用用户提供的页面分配参考。已有团队、三级权限、管理员设置、知识库上传和写手上下文，以及手工内容生产闭环。

## 启动

需要 Node.js 22+、npm 和 [uv](https://docs.astral.sh/uv/getting-started/installation/)。Python 3.12 由 uv 管理。

在项目目录执行，或在 Mac 中双击：

```sh
./start.command
```

启动脚本安装锁定的后端依赖、构建前端，然后在后台同时运行网页服务与独立写作 worker。关闭启动窗口后仍可访问；重复启动先检查健康状态，避免重复创建进程，日志位于 `.data/server.log`。访问 [本地工作台](http://127.0.0.1:8787)。首次启动空数据库时自动创建管理员，默认用户名和密码均为 `admin`；首页只需用户名和密码。已有账号和已修改密码不会被启动过程重置。

1. 使用用户名 `admin`、密码 `admin` 登录，不再需要初始化令牌或管理员姓名。
2. 进入“用户管理”创建团队、IP和用户；给队员分配所属团队的IP。
3. 在“知识库”选择末级目录，上传文件、多文件、文件夹或ZIP，先预览归档位置再确认。知识库由系统内成员共享。
4. 管理员或团队长核验真实资料；模板、说明文档和待核内容不进入事实检索。
5. 在“IP与写手”选择目标IP、基础 Skill，填写12问，再点击“生成 IP Skill”。系统匹配已核验知识，也可手动选定资料。管理员或团队长生成即启用，队员生成后由管理员或团队长启用。
6. 在选题库点“调用写手”，系统转写 TikHub 返回的可读取视频音轨，优先使用本机 Whisper，也支持管理员配置的兼容语音转写服务。核对逐字稿，选择 IP 和写手后提交。模型生成的独立稿件进入审稿，修改时实时检查口播规则和逐字稿重合度。默认计算连续 8 字及以上相同的正文比例，阈值 8%。批准后可安排后续发布。

模型服务地址、模型名称、API Key、飞书、转写、采集、微信与执行器参数均在“系统设置”。系统设置和用户管理只允许管理员操作，服务端也检查权限。保存外部配置不代表已验证连接。文字模型使用兼容 Chat Completions 的接口，地址通常包含 `/v1`。

若暂时没有模型配置，可在素材调用写手时预览并导出提示包，在外部完成写作后到审稿页手工导入。

## 角色

| 角色 | 业务范围 | 批准与核验 | 系统设置与用户管理 |
| --- | --- | --- | --- |
| 管理员 | 全部团队和IP | 可以 | 可以 |
| 团队长 | 所属团队全部IP | 可以 | 禁止 |
| 队员 | 所属团队内明确授权IP | 禁止批准稿件、核验知识和采纳规则 | 禁止 |

成员都可在自己的业务范围内整理选题、上传知识、创建稿件和安排已批准内容。保存用户角色、密码、IP授权或停用状态会撤销该用户既有会话。

## 知识库

- 按截图建立7个主目录、24个末级目录。支持 MD、TXT、CSV、JSON、PDF、DOCX 和 ZIP；每批必须指定一个末级目录，文件夹与ZIP保留原始相对路径。混合主题请按末级目录分批导入。
- 单个知识文件20MB，每批200个文件、解压后80MB；扫描PDF需先OCR。
- 不执行脚本或上传文件里的指令；ZIP路径穿越和符号链接会拒绝。
- 同末级目录下相同路径和内容去重。不同内容保留为不同条目。
- 归档目录与原始路径分别保留。历史资料仅在路径明确匹配时自动分类，其余进入“待归类”。管理员和团队长可调整归档。
- 写稿和改稿从共享库检索已核验且未过期的资料，按任务相关性排序，并参考所选写手 Skill 偏好的知识类别。稿件、目标IP及写手的授权沿用现有范围。
- 修订知识保留旧文本，回到待核状态；已关联稿件的批准失效，未发表排期需要复核。
- 人工稿件可在审稿编辑页选择引用知识（API字段 `source_ids`）；模型生成稿自动保存所引用知识ID。未登记引用的人工稿件无法自动推断知识变更影响。
- 8个分享包能力组成参考库：5种内容文体、3种辅助分析。支持12问专属写手、语感规则与版本快照，辅助模型结果单独管理；不会执行模板中的工具指令。详见[写手与改编说明](docs/写手与改编说明-2026-11-17.md)。

## 数据与密钥

业务数据在 `.data/`，默认仅在本机监听。目录已被 Git 忽略：

| 文件 | 内容 |
| --- | --- |
| `system.db` | 用户、稿件、知识文本、设置、任务与审计；SQLite WAL持久化 |
| `master.key` | 本机加密主密钥；权限600，用于解密系统设置中的凭证 |
| `assets/` | 上传的视频与封面 |

API Key等敏感值在数据库内加密，响应只返回是否已配置；密码为带盐scrypt哈希。不要单独丢失主密钥，否则数据库中的凭证无法解密。前端不保存凭证到localStorage。

项目交付包含源码和运行所需的写手模板，业务数据、备份及本地同步附件单独保管。

飞书默认使用[用户最新的爆款空间模板](https://wcn8zd3z0yjw.feishu.cn/wiki/Me3owpcvFirsbEkqMc9cZ7PLnAf)。管理员可在系统设置选择已授权的本机飞书 CLI，无需复制其密钥；也可使用 App ID / App Secret。系统会先把知识空间节点解析为真实多维表格，再核对博主、作品、评论表及字段。管理员可预览并提交全部现有三表数据；普通用户仍按已有IP与个人权限同步。更换链接后重新配置表ID和字段映射。

截至2026-11-21，CLI权限已生效，完成59条现有材料真实同步和重复验收：637字段读回、6个原公式保留、重复新增0条。已补建知识库与写手SKILL专表，IP和稿件使用原模板表；不写发布/采集触发开关。后来导入的保险存档尚未批量同步到飞书。

写手12问支持填写行业后生成本地参考样例，预览确认后仅填入空白项；已有回答保留，未知资质、价格和案例仍须核实。该功能不调用付费模型，也不自动保存或启用写手。

## 备份与恢复

在项目目录运行：

```sh
uv run --project backend --python 3.12 python -m backend.app.manage backup
```

备份写入新的 `backups/日期时间/` 目录，包含一致的数据库快照、主密钥和上传资产。备份目录含可解密凭证，按内部数据保管。标记 `INCOMPLETE` 的备份不可用于恢复。

恢复时先停止网页服务和worker，把原 `.data` 改名保留，再把完整备份目录复制为 `.data`；执行 `./start.command`。知识库和账号保留，队列中断任务会标失败，不会静默再次调用付费模型。

管理员忘记密码时，在拥有本机文件权限的终端执行：

```sh
uv run --project backend --python 3.12 python -m backend.app.manage reset-password --username 你的管理员登录名
```

交互输入新密码，命令撤销旧会话并记录审计，不创建第二套固定后门账号。

## 开发与测试

```sh
uv sync --project backend --python 3.12 --locked
uv run --project backend --python 3.12 python -m pytest backend/tests -q
npm --prefix frontend ci
npm --prefix frontend run build
```

开发时分别启动服务、worker和前端：

```sh
uv run --project backend --python 3.12 uvicorn backend.app.main:create_app --factory --host 127.0.0.1 --port 8000
uv run --project backend --python 3.12 python -m backend.app.worker
npm --prefix frontend run dev
```

Vite把 `/api` 代理到8000。API文档位于服务端 `/docs`。

浏览器验收使用独立数据目录，不能对已有业务库运行测试。启动测试服务时指定全新的 `ACQUISITION_DATA_DIR`；在 `frontend/` 安装 Playwright Chromium，再执行：

```sh
npx playwright install chromium
npx playwright test
```

测试默认连接8000；可通过 `E2E_BASE_URL` 指定测试地址。已有Chromium可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定。浏览器测试会建立验收账号和样例记录，只能用于隔离的测试空间。

运行时仅支持修改数据目录 `ACQUISITION_DATA_DIR`、本地端口 `ACQUISITION_PORT` 和HTTPS部署时的 `SECURE_COOKIE=1`；这些是进程启动参数。模型与业务集成凭证统一由系统设置管理。

## 当前外部接入范围

模型客户端已用受控本地模型服务验证请求、鉴权和返回入稿；TikHub抖音、小红书、视频号采集与飞书三表同步已实现适配，并使用隔离的接口测试和浏览器验收。飞书已使用授权CLI完成真实同步验收，TikHub仍以隔离接口验证为主。

语音转写、公众号草稿推送、企微外发和Windows RPA目前仍只有集中配置入口，尚未实现对应平台适配与真实联调。上传、暂存或写作建议不等于公开发表或已回复客户。

## TikHub采集与飞书同步

1. 管理员在“系统设置 → TikHub采集”填写 API Key、每日调用预算并启用。地址固定为 `https://api.tikhub.io`。密钥加密保存，其他角色不能读取和修改设置。
2. 选题库优先展示素材列表，默认“全部”，可按实际平台来源、点赞、评论、发布时间或入库时间筛选排序。在下方搜索区填写1至5个关键词，多选抖音、小红书、视频号；归属IP可留空。每词每平台1至5页，每平台最多入库1至20条作品，每作品自动读取1至5页一级评论，提交前显示含视频号详情的调用上界。小红书支持图文和视频笔记。
3. 后台把实际获得的作品放入选题库，把作者加入对标博主，把取得的评论放入客户线索，保留作品与作者关系。未达筛选阈值的作品在“全部”可见。重复内容按归属范围、平台和平台ID去重，保留排除与跟进状态。未归属数据按提交者分开，管理员可见，本团队团队长可见本团队成员素材池，队员仅本人；加入写稿时必须选择有权限的目标IP。
4. 研究评论与可跟进客户分开显示，不计入工作台客户数。意向来自关键词规则，需人工核实；不会自动发消息。视频描述是原文，不是语音逐字稿。“爆款参考”=作品点赞数÷作者同平台、同归属范围已采作品点赞中位数，至少3条有效点赞样本，基线为0不计算。默认3倍可命中参考推荐，另结合低粉高赞、评赞比和起量；不自动认定获客效果。
5. 管理员在“系统设置 → 飞书”保存 App ID / App Secret，为应用开通多维表格读写权限并授权访问用户Base。可填写“博主、作品、评论”的实际表ID，或按同名自动识别；支持JSON显式字段映射。
6. 点击“读取三表与字段”检查匹配结果。“检查并准备同步字段”仅补齐缺失的文本字段 `获客空间ID`、`内容结构`、`获客空间·IP`；不自动新建表、不修改公式。目标字段存在同名但类型不兼容时先报错。
7. 启用飞书后，采集完成会另建同步任务；也可在选题库为选定IP手动同步；未选IP时仅同步本人未归属素材池。按博主→作品→评论顺序写入：完整标准化结构以JSON文本保存，兼容的数值、链接、日期及关联列按实际字段类型写入。同步是本地到飞书的单向镜像，未实现飞书反向导入。
8. 同步前总按 `获客空间ID` 查询；创建超时后需手动重试并先核对，不盲目重建。飞书已映射字段与上次同步快照不一致时暂停，任务可展开字段差异；先人工协调远端/本地值再重试，不提供静默强制覆盖。

采集与同步任务分别显示调用次数、处理数、进度和错误。日预算跨IP共享并在请求前事务计数，错误请求也计入；实际金额以TikHub账单为准。进程中断不会自动重复付费，部分完成数据保留。手动重试采集会按原范围重新请求，已有数据去重；当前不提供自动断点续采。三表同步失败可单独重试，不重新调用TikHub。


视频生成已于2026-11-17撤下：不再提供配置、生成接口与后台调用。原有媒体上传及历史资产保留。

多平台接口依据、范围和权限说明见 [多平台选题库说明](docs/多平台选题库说明-2026-11-17.md)。

## 客户线索查看与口径

客户线索按“来源博主 → 作品 → 评论/线索”树形分组，支持展开/收起、搜索与筛选；未知来源和手工登记单列。关键词意向仅为建议，研究评论不默认计入可跟进量；手工登记沿用原默认口径，尚未核验真实需求和联系路径，数量也不是去重客户人数。详见 [展示与判定标准](docs/客户线索树形展示与判定标准-2026-11-17.md)。

## 评论、需求与写手关联

评论新增内容类型和意向双标签；需求库按目标IP及业务主题整理有效评论，保留原话、来源与透明评分。转选题和写手生成均可关联需求证据快照。操作顺序、统计及权限见 [使用说明](docs/评论需求与写手关联说明-2026-11-19.md)。

## 默认8个写手

分享包8个SKILL现作为默认写手，可在素材中直接调用。知识库更新后自动检索有效知识，长期规则通过IP独立候选、审核、版本和回退完善。详见 [默认写手与知识增强说明](docs/默认8个写手与知识增强说明-2026-11-19.md)。

## 博主发现、作品推荐与帮助中心

- 对标博主支持人工分层、启用/停用、本人账号与备注；关键词搜索发现作者，保留命中词与发现时间。
- 选题库仍默认全部展示，可筛推荐、起量、低粉高赞和时间待核实；每条展示样本、公式分母、命中理由和配置版本。全局阈值仅管理员可在系统设置→作品推荐规则修改。
- 关键词搜索可设置每词和每平台的采集上限，并自动采集指定范围的一级评论。入库后统一使用当前作品推荐规则评估，倍数推荐最低点赞只作用于超基线分支。可用素材指来源可用且未排除、未采用的作品，推荐中的可用素材进入候选池。
- 评论树支持点赞/采集时间排序、标签分布和有效需求筛选；研究评论不自动成为客户。
- 使用说明页按当前实际能力解释采集、知识写手、审稿、单向飞书同步、发布和备份。

详见 [博主发现与作品规则说明](docs/博主发现与作品规则说明-2026-11-19.md)。
